# `data`

*Pebble 0.6.0 · all symbols on this page are stable.*

The Plutus Core `Data` type: a serialization format that every on-chain type can be encoded into and decoded from. Datums, redeemers, and the script context all flow through `data` at the system boundary.

You rarely write `data` directly; the compiler does it for you whenever you use `.toData()` or pattern-match a datum. Reach for raw `data` only when you need to construct or inspect the CBOR shape yourself.

`data` has five constructors (CBOR major types in parentheses):

| Constructor | Shape                                  | Builtin builder                                 |
|-------------|----------------------------------------|-------------------------------------------------|
| Constr      | `(index: int, fields: List<data>)`     | [`std.builtins.constrData`](../Standard%20Library/std.builtins.mdx) |
| Map         | `LinearMap<data, data>`                | [`std.builtins.mapData`](../Standard%20Library/std.builtins.mdx)   |
| List        | `List<data>`                           | [`std.builtins.listData`](../Standard%20Library/std.builtins.mdx)  |
| I (integer) | `int`                                  | [`std.builtins.iData`](../Standard%20Library/std.builtins.mdx)     |
| B (bytes)   | `bytes`                                | [`std.builtins.bData`](../Standard%20Library/std.builtins.mdx)     |

## Operators

| Category | Operators       |
|----------|-----------------|
| Equality | `==`, `!=`      |

Equality is structural CBOR equality, implemented by `equalsData`.

## Working with `data`

```ts
function shape( d: data ): int {
    using { constrData, unConstrData, iData, bData } = std.builtins;

    // Build:
    const built: data = constrData(0, [iData(42), bData(#cafe)]);

    // Destructure a constructor:
    const RawConstr{ index, fields } = unConstrData( d );

    if( index == 0 ) { trace("Some"); }
    else { fail "unknown constructor"; }

    return index;
}
```

`unConstrData` returns a `RawConstr` with two fields, `index: int` and `fields: List<data>`; both
can be destructured in one `const`, as above, and `fields` can be destructured further. *Since
0.6.0* the destructuring works with one property, without the type name, and inside a map entry
(`value: RawConstr{ index }`).

`using { … } = std.builtins;` binds the names in the **block** it appears in — here, the function
body. Put it inside the function or method that uses them; a `using` at file scope is accepted by
the parser but does not bring names into a function's body.

### `Optional<T>.toData()`

An `Optional<T>` has `.toData()` like every other encodable type: `Some{ value: v }` is
`Constr 0 [ v ]`, `None{}` is `Constr 1 []` — the encoding a struct field of that type has.

```ts
function encoding(): bool {
    using { constrData, iData } = std.builtins;
    const some: Optional<int> = Some{ value: 7 };
    const none: Optional<int> = undefined;
    assert some.toData() == constrData( 0, [ iData( 7 ) ] );
    assert none.toData() == constrData( 1, [] );
    return true;
}
```

For most use cases prefer the `.toData()` method (via the [`ToData`](../Builtin%20Interfaces.md#todata) interface) and pattern-matching on the typed value, rather than touching raw `data`.
