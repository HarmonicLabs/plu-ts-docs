# `Array<T>`

*Pebble 0.3.1 · all symbols on this page are stable.*

A fixed-size, indexed container. Built from a `List<T>` via [`std.array.fromList`](../Standard%20Library/std.array.mdx) and consumed via `at(i)` or the index operator.

`Array<T>` is **not** the right answer to "I need fast indexed reads on a `List<T>`". The on-chain cost model bills [`List<T>` indexing](./List.mdx) as effectively constant for practical indices, and `std.array.fromList` itself is O(n) in the list length — so the conversion almost always costs more than the reads you were optimising. See [Cost and Complexity](../reference/Cost%20and%20Complexity.md) for the measured numbers.

Reach for `Array<T>` only when:
- You receive one from elsewhere (an external API, a builtin) and need to read it.
- You're doing many indexed reads against a buffer that you'll keep across many call sites and the amortised conversion is genuinely cheap.

For sequential traversal (`map`, `foldl`, `filter`, ...), use `List<T>` directly.

## Methods

| Method                                       | Description                                                                |
|----------------------------------------------|----------------------------------------------------------------------------|
| `length(): int`                              | Number of elements. O(1).                                                  |
| `at(i: int): T`                              | Element at index `i`. Fails on out-of-bounds.                              |

### Examples (one per method)
```ts
const xs: Array<int> = std.array.fromList([10, 20, 30]);

const n: int = xs.length();   // 3
const v: int = xs.at(1);      // 20
```

## Indexing

`xs[i]` is sugar for `xs.at(i)`. Both are O(1).

## Constructing

`Array<T>` has no literal form. Build one from a list:

```ts
const xs: Array<int> = std.array.fromList([1, 2, 3]);
```
